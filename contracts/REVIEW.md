# Проверка контракта 2026-11-09

## Вывод

v0.1 была пригодна как общий эскиз, но оставляла важные решения на усмотрение разных
разработчиков. v0.2 дает согласованный контракт для независимой реализации Go и React
в границах одного выбранного сценария. Это результат анализа спецификации и проверки
примеров, а не доказательство работоспособности еще не написанного приложения.

## Исправления

| Проблема v0.1 | Последствие | Решение v0.2 |
|---|---|---|
| Нет ключа повтора создания диалога | Два диалога после потери POST-ответа | client_conversation_id, повтор возвращает прежний объект |
| Для прямого URL нужен весь список диалогов | Лишняя зависимость экрана от списка | GET /conversations/{conversation_id} |
| Ответ не ссылается на исходный вопрос | Неоднозначное восстановление после сбоя | in_reply_to_message_id |
| Сортировка по времени без разрешения равенства | Перестановка user/assistant | Серверный порядок записи |
| SSE описан только Markdown-таблицей | Ручные несовместимые типы событий | ChatEvent и схемы всех 7 событий в OpenAPI |
| Нет разрешенных переходов шага | UI угадывает доступность кнопок | allowed_statuses, blocked_reason и нормативные правила PATCH |
| Нет точной формулы прогресса/null next_step | Разное поведение экрана и Go | Формула, порядок и значения null в behavior.md |
| Кеш сравнивается по времени | Поздний ответ может откатить статус | Монотонная revision; draft_version отвечает только за параметры |
| Неясен повтор confirm со старой версией | Повторная отправка либо ложный конфликт | Таблица проверки состояния до версии |
| Нет восстановления отправки после рестарта | Потерянная/дублированная заявка | Сохраненная операция, внешний ключ идемпотентности и сверка |
| Нет стабильной таблицы error.code | Фронт начинает анализировать русский текст | Таблица кодов и явные HTTP-ответы в OpenAPI |
| Нет согласованных JSON-примеров | Разные моки и неполные поля | scenario.json и автоматический валидатор |
| История может вечно оставаться generating | Бесконечный polling | Лимит сервера, восстановление рестарта и граница ожидания UI |

## Проверки

`scripts/check_contracts.py` проверяет структуру OpenAPI, уникальность operationId,
примеры запросов/ответов/SSE, формат UUID/дат, связь вопроса с ответом, связи заявки,
формулу прогресса и ревизии. Негативные случаи проверяют отказ при пропуске важных
полей и отправке пробельного вопроса. Локальные Markdown-ссылки проверяются автоматически.

## Что остается за реализацией

- Go: транзакции, блокировки, проверка прав, хранение прогресса генерации и очереди отправки.
- React: реальные сетевые обрывы, гонки двух вкладок, работа reader и безопасный рендеринг.
- Интеграции: поддержка idempotency key/сверки внешней заявки и воспроизводимые demo-переходы.
- Команда: реальная генерация TypeScript-типов и runtime-схем, интеграционные тесты,
  измерение покрытия >80%, SDD поведения агента и проверка с LLM.

Увеличение числа сценариев, пагинация, полноценная корпоративная авторизация и кабинет
наставника требуют следующей согласованной версии. Redis/Kafka/Kubernetes для текущего
контракта не обязательны.
