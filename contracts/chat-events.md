# Поток чата — контракт v0.1

POST `/api/v1/conversations/{conversation_id}/messages` отправляется через `fetch`
с JSON, cookie сессии и `Accept: text/event-stream`. Ответ читается через ReadableStream.
Один сетевой chunk не равен одному событию: клиент собирает строки до пустой строки,
учитывает UTF-8 на границах chunk и допускает LF/CRLF.

Сервер: `Content-Type: text/event-stream`, `Cache-Control: no-cache`.
Прокси не буферизует поток. Комментарий `: heartbeat` допустим и игнорируется клиентом.
События содержат JSON в `data`. Внутренние рассуждения модели не передаются.

## События

| event | data | Смысл |
|---|---|---|
| message.started | `{user_message_id, message_id}` | Сообщение пользователя и заготовка ответа сохранены |
| tool.started | `{message_id, tool_call_id, label}` | Пользовательская подпись, например «Проверяю доступ» |
| tool.finished | `{message_id, tool_call_id, status}` | status: `succeeded` или `failed`; это не статус заявки |
| answer.delta | `{message_id, text}` | Дописать text к ответу |
| action.proposed | `{message_id, request}` | request — полная AccessRequest из OpenAPI в статусе draft |
| message.completed | `{message}` | message — полная Message, status=completed; заменить накопленную версию |
| message.failed | `{message}` | Полная сохраненная Message, status=failed, с error в формате ApiError |

`message.started` всегда первое. Затем события инструментов, предложения действия
и текст могут чередоваться. tool_call_id связывает начало и завершение одного вызова.
Поток завершается ровно одним message.completed или message.failed, затем закрывается.
Порядок событий внутри соединения сохраняется. Финальное сообщение содержит весь текст,
источники и request_ids, в том числе если текст был накоплен без answer.delta.
action.proposed передается только после сохранения черновика и связи с сообщением.

Пример фрагмента потока:

```text
event: message.started
data: {"user_message_id":"msg_u1","message_id":"msg_a1"}

event: tool.started
data: {"message_id":"msg_a1","tool_call_id":"call_1","label":"Проверяю доступ"}

event: tool.finished
data: {"message_id":"msg_a1","tool_call_id":"call_1","status":"succeeded"}

event: answer.delta
data: {"message_id":"msg_a1","text":"Для работы нужен доступ к репозиторию."}

```

## Обрыв и повтор

До открытия потока ошибки возвращаются обычным HTTP-ответом ApiError.
После открытия — message.failed, если соединение еще доступно.
EOF без терминального события означает потерю соединения, но не доказанный отказ операции.
Фронт загружает GET messages. Если ответ еще generating, повторяет GET с интервалом 2 с,
не запускает новую генерацию; сервер должен завершить отмену либо обработку и сохранить статус.
Сервер ограничивает одну генерацию 120 секундами (включая вызовы инструментов).
При перезапуске сервера незавершенные генерации переводятся в interrupted.

При неопределенном исходе отправки повторяется исходный client_message_id.
409 MESSAGE_ALREADY_EXISTS означает загрузить историю. Осознанный повтор после failed/interrupted
создает новое сообщение с новым UUID. Автоматического SSE replay / Last-Event-ID в MVP нет.
Закрытие страницы отменяет генерацию, но не уже подтвержденную отправку заявки.

## Подтверждение действия

Фронт показывает ресурс, право доступа, причину и кнопку подтверждения из сохраненного черновика.
POST confirm выполняется только после явного нажатия пользователем, а не по тексту ответа LLM.
Агент не имеет права самостоятельно вызывать публичное подтверждение от имени пользователя.
Для изменения параметров пользователь пишет уточнение в чат: агент обновляет только draft,
увеличивая draft_version. Старое подтверждение получает 409 DRAFT_CHANGED.
Уже отправленные заявки агент не редактирует.
После confirm фронт обновляет карточку заявки и план; при 202 опрашивает GET заявки раз в 5 с.
При повторе confirm для failed сервер может повторить отправку только если отсутствие внешней
заявки достоверно установлено; для rejected/granted возвращает текущее состояние без нового действия.

Номер заявки отображается из external_id, а не извлекается из сгенерированного текста.
pending означает ожидание согласования; только granted означает подтвержденный доступ.
