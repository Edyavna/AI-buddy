# FE2 — каркас, план адаптации и заявки

Сначала прочитать README.md и integration.md этой папки. Владение файлами указано там.

## Результат работы

Стажер входит тестовым пользователем, видит план и следующий шаг, переходит в чат,
подтверждает подготовленную заявку и видит ее реальный сохраненный статус.
Главный общий компонент — AccessRequestPanel, который FE1 использует в чате.

## Порядок реализации

### Шаг 1. Быстро передать каркас

- Создать один frontend/ с React + TypeScript strict, Vite, router и QueryClientProvider.
- Зафиксировать Node, npm, lockfile и scripts; согласовать тестовые scripts с FE1.
- Настроить proxy /api → Go в dev, не вшивать адрес localhost в компоненты.
- Маршруты и AppShell; временный слот ChatPage без реализации собственного чата.
- Базовые стили, Button, InlineError, Spinner и Drawer передать FE1 первыми.
- Пакеты устанавливаются через общий package.json, а не в отдельном проекте каждого.

### Шаг 2. Сессия и план

- Demo accounts → createDemoSession → getMe → onboarding.
- Сессия в HttpOnly cookie, пароль/токен не хранить в localStorage.
- Общая обработка 401; при смене пользователя очистить QueryClient и stream-state FE1.
- Plan: серверные progress_percent, next_step_id, упорядоченные steps.
- Карточки шагов: описание, status, связанные request_ids, «Спросить помощника».
- PATCH статуса: на время запроса блокировать повтор; записать возвращенный Plan.
- Кнопки изменения шага строить по allowed_statuses; blocked_reason объясняет блокировку.
- Не выставлять blocked вручную. При 409 показать причину и обновить план.
- next_step_id=null — не придумывать следующий шаг; показать состояние согласно данным плана.

### Шаг 3. Поставить карточку для чата

- Runtime-схема AccessRequest и acceptAccessRequest для приема HTTP/SSE данных.
- AccessRequestPanel и внутренний AccessRequestCard по integration.md.
- Все шесть статусов, external_id, status_checked_at, loading/not-found/error.
- Confirm с draft_version; pending-флаг общий на requestId для нескольких экземпляров.
- Обработка DRAFT_CHANGED, 202, неизвестного сетевого исхода, failed/rejected.
- Polling и обновление plan/requests; без самостоятельного создания заявок из UI.
- Изменить черновик можно через разговор с агентом, а не прямой PATCH несуществующего API.
- Дать FE1 готовый экспорт и тестовую карточку как можно раньше, до полировки всего плана.

### Шаг 4. Довести общий интерфейс

- Loading, пустые состояния, ошибки с повтором, небольшие экраны и клавиатура.
- Общие Dialog/Drawer: фокус, Escape, закрытие и возврат фокуса.
- Список заявок можно встроить в план; отдельная страница для MVP не требуется.
- Отдельный кабинет наставника, редактор планов и одобрение собственной заявки не делать.

## Тесты твоей зоны

- Вход/выход/смена аккаунта без утечки старого кеша; 503 не трактуется как 401.
- Переход из шага передает stepId, не отправляет сообщение автоматически.
- PATCH ошибки и успешное обновление прогресса данными сервера.
- Confirm отправляет отображенную draft_version; двойное нажатие/две карточки не дублируют mutation.
- При 409 DRAFT_CHANGED появляется новая карточка и требуется новое подтверждение.
- 202/submitting/pending не выглядят как выданный доступ.
- Polling останавливается на конечном статусе и скрытой вкладке; возобновляется при возвращении.
- Старое action.proposed не откатывает подтвержденную заявку в draft.
- Обновление страницы сохраняет номер и статус через API.
