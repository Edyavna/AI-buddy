# Персональная память стажёра — #79

База после ревью PR #82 — `dev fe66ca1`, ветка `feature/intern-personal-memory`.
Используются существующие cookie-сессии, Origin, роли, команды, назначения, план, заявки и чат.
Миграция `000028_personal_memory.sql` добавляет предложения, результаты отбора, подтверждённые
записи и квитанции удаления. Существующие диалоги и данные плана не переписываются.

## Объединение с dev и исправления ревью

Сохранены контекст отправленных обращений, рекомендации, архив, обычный чат наставника,
Markdown-режим и восстановление доступа из dev. Профиль оборачивает только исполнителя
стажёра; интерфейс наставника не запрашивает и не отображает память стажёра.
Видимость проверяет фактическую роль intern, включая прямой переход наставника на /chat.
Миграция 000028 идёт после выпущенной 000027. PostgreSQL-тест проверяет обновление поверх
dev и повторные Apply/Verify с сохранением архивного Markdown-диалога.

Регрессионные тесты сначала воспроизвели и затем подтвердили исправление двух ошибок:
обёртка сохраняет ConversationTitle подключённого агента, а память не использует источники
из недоступных стажёру Markdown-диалогов наставника. Ограничение действует для отбора,
подтверждения, списка, прямого чтения, редактирования, удаления и контекста модели.
Архив обычного диалога остаётся доступным источником.

Предложения помещены в прокручиваемую историю: длинные карточки не сжимают её до нуля
и не выталкивают поле ввода. Браузерная проверка видимости поля/кнопки сначала падала,
затем прошла на 360/768/1440. В CI вместе с памятью выполняются сценарии чата наставника
и генерации Markdown; все три проверяются также после restart/reseed.

## Пользовательский путь

Стажёр сообщает: «Я работаю на Windows и использую PowerShell». После ответа в чате появляются
предложения с формулировкой и ссылкой на собственную исходную реплику. «Запомнить» — явное
подтверждение; «Не сохранять» отклоняет предложение. До подтверждения факт не попадает в профиль.
Повтор подтверждения возвращает существующую запись. Reload не запускает повторный отбор
для уже обработанной реплики и не создаёт дублей.

«У меня ОС Windows» и «работаю на винде» могут дать ту же карточку «Работаю на Windows».
Когда факт лишь предположительно относится к стажёру, карточка показывает пометку «Возможно,
это ваше предпочтение». Короткая просьба «запомни это» использует предыдущую реплику
пользователя в том же диалоге, если та подходит для отбора. Карточка ссылается на эту реплику
и переиспользует уже созданное предложение. Запись появляется после нажатия «Запомнить».

«Моя память» доступна из чата по `/memory`. Здесь показаны текущая команда, наставник и прогресс,
ожидающие подтверждения предложения, сохранённые предпочтения, источник и дата. Запись можно
исправить и удалить. Исправление отмечается как ручное; ссылка остаётся на реплику, из которой
возникла исходная запись. Раздел «Что учитывает помощник» показывает фактический профиль данных.

При замене предпочтения показано прежнее значение. Подтверждение сравнивает ID **и** ревизию
заменяемой записи. Изменение другой вкладкой даёт `409 MEMORY_CHANGED`; локальный выбор
сохраняется до явного перечитывания/отмены. OS, оболочка и формат инструкций имеют по одному
текущему значению; изучаемые технологии — отдельные записи для каждой технологии.

Удаление физически убирает запись и связанные с ней принятые предложения. Остаётся квитанция
с ID, владельцем, ревизией и датой, без значения и текста источника. Повтор DELETE той же
ревизии идемпотентен. Только владельцу квитанции GET возвращает `404 MEMORY_ENTRY_DELETED`.
Обычный 404 при потерянном ответе не считается доказательством удаления. Старое подтверждение
удалённого предложения не восстанавливает запись; для нового сохранения нужна новая реплика
и новое явное подтверждение. Исходное сообщение продолжает существовать в истории чата.

В следующем диалоге помощник получает новый серверный профиль. PowerShell даёт команды для
PowerShell; изменение на Bash и удаление заметны в следующем запросе. Наставник, прогресс и
заявки перечитываются из БД при каждом запросе, а не сохраняются в пользовательскую память.
Смена назначения поэтому не оставляет в новом контексте прежнего наставника.

## Границы и безопасность данных

Хранятся **структурированные значения** трёх категорий: `work_environment`, `learning`,
`instruction_format`. Серверный каталог содержит Windows/Linux/macOS; PowerShell/Bash/Zsh/CMD;
Go, TypeScript, JavaScript, React, Python, Java, Docker, PostgreSQL, Git, Node.js, Kubernetes;
пошаговый, краткий, подробный формат и инструкции с примерами. Редактирование выбирает значение
из того же каталога. Свободный текст модели не становится значением памяти.

Реплика ограничена 1000 символами, отбор — четырьмя предложениями, дословная опора — 200 символами.
Сервер отсеивает явный отказ от сохранения, ограничение текущим разговором и реплики с признаками
секретов, персональных кадровых сведений, документов и управляющего содержимого. Название из каталога,
разговорный вариант или признак формата инструкций запускает отбор. Без этих признаков состояние
становится `skipped` до вызова модели. `Model.Select` повторяет проверку перед внешним запросом.

Внешняя модель получает только найденные разрешённые фразы и каталог; посторонний текст не передаётся. Она оценивает контекст, в том числе отрицания,
упоминания коллег, цитаты и прошлые предпочтения. Сервер принимает только значения каталога с дословной
цитатой, в которой есть опора для этого значения. При недопустимом ответе весь отбор получает `failed`.
Сервер проверяет принадлежность исходной реплики до и после вызова модели и при подтверждении.
Текст реплики и цитата модели хранятся только в исходной истории чата.

Подбор выполняется отдельным запросом **после** завершения ответа чата. Вызов модели ограничен
тремя секундами; внешний контекст отбора — четырьмя. Сбой/тайм-аут даёт состояние `failed`,
не создаёт запись, не прерывает обычный чат и допускает явный повтор. В live-режиме используется
модель из существующей AI-конфигурации; автоматической замены её ответа демо-правилами нет.
В явно включённом demo-режиме используется детерминированный селектор.

Чтение, прямые запросы, подтверждение, изменение, удаление и квитанции доступны только владельцу
со статусом intern и текущей командой. Чужой ID даёт обычный 404. Наставник и HR не получают
доступ к чужим предпочтениям. Операции сериализуются на владельце, повторная запись не создаёт
несколько значений одного слота. Модель не задаёт владельца, команду, роль, назначение или статус.

Профиль Markdown ограничен **4096 байтами**. Он содержит свежие данные приложения, подтверждённые
предпочтения, сводку статусов заявок и до пяти недавних заявок без причин и внешних номеров.
Имена экранируются как строковые данные; строки добавляются целиком в пределах лимита.
Профиль передаётся модели в пользовательском контексте, отдельно от системного промпта и
проверенного контекста чекпоинта. Он не меняет полномочия, назначения и переходы заявок;
существующие серверные проверки инструментов сохраняются. HR-ответ получает те же данные
отдельным полем, не расширяя набор доступных документов.

При недоступности чтения необязательного профиля агент использует пустой профиль вместо старого
кеша. При отказе прав работа прекращается. Logout/смена аккаунта очищают общий session scope.
Отказ 401/403/404 в чтении **или мутации** очищает все клиентские копии памяти и отменяет старое
поколение запросов. Поздний 200 и последующая 503 не восстанавливают закрытые/удалённые значения.

Временные записи, сроки действия, произвольные заметки и автоматическое подтверждение не добавлены.

## API и примеры

Пути относительно `/api/v1`. [OpenAPI](../../contracts/openapi.yaml),
[типизированные примеры](../../contracts/examples/personal-memory.json).

| Метод и путь | Результат |
| --- | --- |
| `GET /memory` | Свои записи, ожидающие предложения, каталог и свежий профиль |
| `GET /messages/{id}/memory-proposals` | Состояние отбора и предложения из собственной user-реплики |
| `POST /messages/{id}/memory-proposals` + `{}` | Отбор без подтверждения; готовый результат повторно не генерируется |
| `PUT /memory/proposals/{id}` | Явное решение с проверкой заменяемой записи |
| `GET /memory/entries/{id}` | Собственная доступная запись или квитанция удаления в ApiError |
| `PUT /memory/entries/{id}` | Исправление `{value, revision}` |
| `DELETE /memory/entries/{id}` | Удаление `{revision}`, успешный ответ `{deleted:true}` |

Подтверждение новой записи:

```json
{"decision":"accept","expected_entry_id":null,"expected_revision":0}
```

Для замены передаются ID и ревизия из `proposal.replaces`. Для отказа используется
`decision: "dismiss"`. Ключи операций в этих маршрутах — собственные ID предложений и
ID/ревизии записей; дополнительный клиентский UUID не нужен. При неизвестном исходе клиент
перечитывает состояние предложения/записи; неподтверждённый успех не показывается.

## Проверка из чистой среды

Нужны Docker Compose, Node из `frontend/.node-version`, Go 1.26.5; Git нужен тестам Playbook
из уже включённого в dev #73. Команды ниже — bash из корня; PowerShell использует `$env:`.
Не удаляйте рабочий том БД для проверки restart.

```bash
npm --prefix frontend ci
export COMPOSE_FILE=compose.yaml:scripts/compose.hr-test.yaml
docker compose up --build --wait --wait-timeout 180 frontend hr-fixture
docker compose --profile demo run --rm seed
npm install --no-save --package-lock=false playwright-core@1.60.0
npx playwright-core install --with-deps chromium
node scripts/personal-memory-browser.mjs
docker compose exec -T db psql -U buddy -d buddy -v ON_ERROR_STOP=1 -c "UPDATE mentor_assignments SET mentor_id='mentor_demo_2' WHERE intern_id='intern_demo_1'"
docker compose restart api hr-fixture
docker compose up -d --wait api hr-fixture
docker compose --profile demo run --rm seed
node scripts/personal-memory-browser.mjs --verify
```

Сайт — `http://localhost:5173`; демо-аккаунт «Тестовый стажер». Пример реплики для
детерминированной приёмки: «Я работаю на Windows и использую PowerShell. N79».
В новом диалоге: «Как проверить текущую папку? N79». Измените запись на Bash, повторите
в новом диалоге, затем удалите и убедитесь, что предпочтение больше не используется.
Маркеры N79 нужны только внешней тестовой фикстуре, не селектору или бизнес-API.

Скрипт проверяет 360/768/1440 px, клавиатуру, источники, отказ от сохранения, повтор/reload,
новый диалог, изменение, удаление, изоляцию второго стажёра, сбой модели и недопустимую реплику.
`--verify` проверяет сохранность после restart/reseed и **нового наставника в ответе модели**.
Артефакты — `tmp/personal-memory-browser/`; можно задать `MEMORY_BROWSER`,
`MEMORY_PLAYWRIGHT_MODULE`, `MEMORY_APP_URL`, `MEMORY_SCREENSHOTS`.

В браузерной приёмке работают настоящие Go, PostgreSQL и cookie-сессии; заменён только
внешний AI-провайдер. Live-модель с настоящим ключом не проверялась. Для реального провайдера
используется существующий `AI_MODE=live` и AI-конфигурация проекта.
