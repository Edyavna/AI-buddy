# Один ответ на повторяющиеся вопросы — #58

Ветка `feature/shared-question-resolutions`, база `dev` — `4210ed9`.
Используются уже объединённые #56 (черновики инструкций) и #62 (HR, области,
версии документов). Изменения аддитивны: старые маршруты вопросов и публикации
сохраняются; личные вопросы не превращаются в искусственные групповые обращения.
Миграция `000018_question_groups.sql` добавляет отдельные таблицы групп, состава,
аудита и групповых черновиков, не переписывая существующие данные.

## Пользовательский сценарий

1. Наставник или HR открывает «Вопросы» → «Один ответ на похожие вопросы».
   Наставнику доступны открытые вопросы назначенных стажёров. HR доступны открытые
   обращения, которые он взял в работу, в активной области обслуживания.
2. Предложения показывают общие слова и совпадение чекпоинта. Можно выбрать пару,
   изменить состав, исключить неподходящий вопрос либо создать группу вручную
   из 1–30 вопросов. Все участники принадлежат одной команде и направлению.
   Подтверждение всегда явное; похожесть не изменяет обращения автоматически.
3. Автор вводит название темы и общее решение без личных подробностей. Сохраняются
   автор, команда, направление, ревизия, состав, решение и история изменений.
   Вопрос одновременно состоит максимум в одной активной группе.
4. «Подготовить общую инструкцию» открывает существующий редактор #56. В генерацию
   передаются только вручную составленные тема и решение. Имена, индивидуальный
   контекст, тексты участников и чекпоинты автоматически в модель не переносятся.
   Предложение модели редактируется, сохраняется и публикуется только после
   отдельной отметки проверки текста и аудитории. Редактор допускает и ручной текст.
5. Используются публикация Markdown, дополнение доступного документа, очереди
   индексации, версии и повтор индексации #56/#62. До постановки в очередь сервер
   заново проверяет всех участников, назначения, состояние и команду. Текущий
   групповой контекст не меняет существующие персональные черновики.
6. Готовность документа сама по себе не закрывает и не меняет вопросы.
   «Доставить или повторить ссылки» проверяет каждого получателя и версию документа,
   добавляет ссылку в его вопрос и сохраняет результат отдельно по участникам.
   Стажёр открывает источник через собственное обращение в обычном чате.
   Чужие обращения и группы ему недоступны.
7. «Закрыть доставленные вопросы» — отдельное явное действие. Только успешно
   доставленные и неизменённые обращения получают общее решение и статус resolved.
   Конфликт или отказ по одному участнику сохраняет успех остальных. После проверки
   состава и обновления ревизий можно повторить незавершённую часть.

## Согласованность, доступ и восстановление

- Создание идемпотентно по клиентскому UUID и нормализованному запросу. Повтор
  возвращает ту же группу. Другой запрос с тем же UUID получает 409. Обновления
  используют ревизию; участники блокируются в стабильном порядке, активный состав
  защищён уникальным индексом. Повтор доставки/закрытия не дублирует ссылки и аудит.
- Неизвестный результат сетевой операции сверяется через GET. До сверки повтор
  создания использует прежние UUID и состав. Успех не показывается без ответа
  сервера. Кнопки защищены от повторного клика; запросы ограничены по времени.
- «Перечитать версию» сверяет форму с последней принятой серверной версией.
  Нетронутые название, решение и состав обновляются; независимые локальные правки
  сохраняются. Если одно поле изменено с двух сторон, показаны оба варианта и
  требуется явный выбор для каждого конфликта. До выбора сохранение заблокировано,
  включая отправку формы с клавиатуры. Повторное перечитывание не подтверждает
  старый локальный текст автоматически; новая серверная правка вновь защищена
  ревизией. После начала публикации локальный вариант текста можно скопировать,
  но принять для сохранения разрешено только зафиксированный серверный текст.
- После начала публикации тема и решение фиксируются. После готовности можно
  исключать участников и обновлять проверку ревизий оставшихся, но нельзя тихо
  добавлять новых адресатов к уже проверенному материалу.
- Автоматического слияния групп нет. Чтобы объединить связанные группы или
  выпустить новое общее решение, автор явно архивирует их состав, затем создаёт
  новую группу и заново проходит редакторскую проверку. История и уже доставленные
  ссылки остаются; открытые вопросы освобождаются для нового состава.
- Смена наставника/ответственного HR освобождает прежнее активное членство только
  при создании группы новым законным ответственным, с записью `owner_changed`
  в старой истории. Старое решение и закрытые данные ему не передаются.
- Чужая группа возвращает 404; стажёру маршрут специалиста возвращает 403.
  Недоступный участник имеет `question: null`, без прежнего текста/имени. Отзыв
  доступа, logout, поздний успешный ответ и следующая 503 не восстанавливают кеш.
- Если опубликованная версия отозвана или заменена, группа и её история остаются
  доступны автору в текущей области, а подробности черновика скрываются. Возвращается
  `publication_error`, доставка блокируется. Можно архивировать состав и начать
  новое решение. Архивирование до индексации препятствует публикации старой группы.
- Группы, черновики, статусы, ссылки и аудит хранятся в PostgreSQL. Reload,
  перезапуск API и повторный seed проверены. Авторизация, cookie, Origin, общие
  ApiError и выдача документов остаются в существующих модулях.

## Критерии сходства и метрики

Подбор детерминированный, без LLM: нижний регистр, `ё` → `е`, слова от трёх знаков,
стоп-слова, консервативное удаление русских окончаний. Jaccard по множествам слов.
Предложение возникает при ≥2 общих словах и коэффициенте ≥0,35 либо при общем
чекпоинте, ≥1 общем слове и коэффициенте ≥0,18. Перед подбором фильтруются состояние,
направление, команда, текущие назначения/область и активное членство. Контекст и имена
не участвуют. Название темы задаётся человеком; оно используется для оценки повторов.

Окно — последние 100 доступных открытых вопросов, максимум 30 пар-предложений;
рабочее место показывает до 100 последних собственных доступных групп, история —
100 последних событий. Это ограниченная выборка, не полный поиск по всей базе.
`limited` обозначает усечение кандидатов. `repeat_count` считает по одному каждый
новый доступный вопрос в той же команде/направлении, созданный после первой успешной
публикации и похожий на название темы. Все когда-либо входившие в группу вопросы
исключаются. Проверяются первые 500 новых вопросов; при превышении устанавливается
`repeat_count_limited`, UI показывает «не менее». Числа участников и доставок относятся
к текущему составу/текущей доступной области; прошлый состав сохраняется в аудите.

Размеченный синтетический набор: `demo/question-similarity-eval.json`, 32 пары.
Результат: TP=15, FP=1, FN=1, TN=15; precision=93,75%, recall=93,75%, accuracy=93,75%.
Это проверка правил, а не оценка на пользовательских данных. Противоположные намерения
с одинаковыми словами могут дать ложное совпадение; перефразирование без общих слов
может быть пропущено. Поэтому предложения требуют ручного подтверждения.
Генерация инструкции проверена с детерминированной HTTP-имитацией модели и embeddings;
живую внешнюю модель в этой поставке не проверяли.

## API

Общий префикс: `/api/v1/{mentor|hr}/question-groups`.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | префикс | Группы, кандидаты, объяснимые предложения, признак лимита |
| POST | префикс | Подтверждение состава с новым UUID, `revision: 0` |
| GET | `/{id}` | Группа, статусы участников, безопасный черновик, история, метрики |
| PUT | `/{id}` | Изменение состава/решения по ревизии; пустой состав архивирует |
| POST | `/{id}/deliver` | Доставка готовой версии каждому разрешённому получателю |
| POST | `/{id}/close` | Явное закрытие успешно доставленных вопросов |
| GET/PUT/POST | `/{id}/instruction-draft…` | Тот же контракт редактора #56: workspace, save, targets, generate, publish, retry |

```json
{
  "operation_id": "58585858-5858-4585-8585-585858585858",
  "revision": 0,
  "title": "Оформить доступ к сервису",
  "resolution": "Создайте заявку и дождитесь согласования.",
  "question_ids": ["11111111-1111-4111-8111-111111111111"]
}
```

`deliver` и `close` принимают `{"revision": 1}`. Конфликт состава, назначения,
состояния или уже связанного вопроса — 409 `GROUP_CHANGED`; неправильный запрос —
422. Примеры и негативные проверки входят в `contracts/examples/question-groups.json`
и `scripts/check_contracts.py`; TypeScript обновлён штатным генератором.

## Воспроизведение через браузер из чистой среды

Используйте отдельный Compose-проект/том. Если порты заняты, освободите их для
тестового проекта или задайте собственные host ports в override.

```sh
docker compose -p buddy-issue58 -f compose.yaml -f scripts/compose.hr-test.yaml up --build --wait frontend hr-fixture
docker compose -p buddy-issue58 -f compose.yaml -f scripts/compose.hr-test.yaml --profile demo run --rm seed
docker compose -p buddy-issue58 -f compose.yaml -f scripts/compose.hr-test.yaml exec -T db psql -U buddy -d buddy -v ON_ERROR_STOP=1 -c "UPDATE mentor_assignments SET mentor_id='mentor_demo_1' WHERE intern_id='intern_demo_2'"
npm install --prefix tmp/group-browser-tools --no-save --package-lock=false playwright-core@1.60.0
npx --prefix tmp/group-browser-tools playwright-core install chromium
```

Задайте `GROUP_APP_URL=http://localhost:5173`, `GROUP_PLAYWRIGHT_MODULE` — абсолютный
путь к `tmp/group-browser-tools/node_modules/playwright-core/index.mjs`; при необходимости
`GROUP_BROWSER` — путь к установленному Chrome/Chromium. Скрипт создаёт синтетические
данные и использует обычные UI-маршруты с настоящими Go и PostgreSQL:

```sh
node scripts/question-groups-browser.mjs
docker compose -p buddy-issue58 -f compose.yaml -f scripts/compose.hr-test.yaml restart api hr-fixture
docker compose -p buddy-issue58 -f compose.yaml -f scripts/compose.hr-test.yaml up -d --wait api hr-fixture
docker compose -p buddy-issue58 -f compose.yaml -f scripts/compose.hr-test.yaml --profile demo run --rm seed
node scripts/question-groups-browser.mjs --verify
```
