# Подготовка к ревью PR (#59)

Стажёр прикрепляет ссылку на PR, проходит чек-лист команды и отправляет наставнику
одну карточку: ссылка, резюме, выполненный чек-лист, результаты проверок с источником
и вопросы. Наставник открывает подготовленную карточку со ссылкой и кратким резюме.

## Маршруты

- Стажёр: `GET/POST /api/v1/review-preparations`, `GET/PUT /api/v1/review-preparations/{id}`,
  `POST /api/v1/review-preparations/{id}/submit` (явное подтверждённое пользователем действие),
  `POST .../assistant` (помощь с описанием и пропущенными пунктами),
  `POST .../refresh` (синхронизация сведений о PR, только режим интеграции GitHub).
- Шаблон: `GET /api/v1/review-preparations/template` (любая роль),
  `PUT` — только наставник, с проверкой revision.
- Наставник: `GET /api/v1/mentor/review-preparations[?intern_id=]`,
  `GET /api/v1/mentor/review-preparations/{id}` (карточка с историей ревизий).

## Режимы сведений о PR

- Интеграция GitHub включена переменными `GITHUB_TOKEN` / `GITHUB_API_URL`: сервер подтягивает
  title, head-коммит и check-runs. 404 → явное сообщение о недоступном репозитории;
  403/429 с исчерпанным лимитом → `GITHUB_RATE_LIMIT`; отсутствие CI → пустой список проверок.
  Сбой интеграции не отменяет черновик: ошибка сохраняется в `pr.fetch_error`.
- Без токена — ручной режим: сведения и результаты заполняет стажёр.

## Состояния и история

`draft` → `submitted` (явная отправка). Повторная отправка отправленной подготовки создаёт
новую ревизию; снимок предыдущей ревизии фиксируется в `review_preparation_history` и виден
наставнику. Конкурентные изменения защищены проверкой `revision` (409 `REVIEW_CHANGED`).
У стажёра не больше одного черновика (частичный уникальный индекс).

Результаты проверок хранятся с обязательным источником: `intern` (указал стажёр, заменяются
при сохранении) и `ci` (получены интеграцией, привязаны к head-коммиту, заменяются при refresh).
Обновление head-коммита отвечает `changed=true` — UI предлагает сверить резюме.

Итоговое принятие результата наставником выполняется через существующее подтверждение
чекпоинта плана; фича ничего не пишет во внешний PR.

## БД

Миграция `000013_review_preparation.sql`: `review_checklist_templates`,
`review_preparations` (+ частичный уникальный индекс одного черновика),
`review_preparation_checks`, `review_preparation_history`.

## UI

- Стажёр: `/review-preparation` — создание по ссылке (валидация адреса в UI и на сервере),
  чек-лист команды, резюме/проверка/ограничения/вопросы, редактор ручных проверок,
  панель ассистента с вставкой в описание, двухшаговое подтверждение отправки,
  кнопка проверки обновлений PR в режиме интеграции.
- Наставник: `/mentor/review-preparations` — список карточек и редактор шаблона чек-листа
  команды; `/mentor/review-preparations/:id` — ссылка, описание, чек-лист, результаты
  с бейджами источников, вопросы, история отправок.

## Проверки

- Backend: `go vet ./...`, `go build ./...`, `go test ./...` (unit без БД; интеграционные
  тесты store/HTTP требуют `TEST_DATABASE_URL`, в CI — сервис PostgreSQL).
- Frontend: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run check:api`.
- Контракт: `python scripts/check_contracts.py`.
