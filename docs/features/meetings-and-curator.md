# Встречи 1:1 и обзор адаптации

## Встречи

В демо войдите как `intern_demo_1` или `mentor_demo_1` и откройте «Встречи 1:1». Создайте встречу, добавьте общую либо личную тему, перенесите или завершите встречу. Итоги и договорённости сохраняются одной транзакцией. Договорённости показываются в плане и доступны для выполнения ответственным. Они не участвуют в расчёте прогресса по чекпоинтам.

Обе стороны должны по-прежнему состоять в том же назначении. Личная заметка видна её автору. В автоматическую повестку попадают изменения чекпоинтов, текущие блокеры, открытые рабочие вопросы и незавершённые договорённости. Начало периода исключает момент завершения предыдущей встречи. У исторических чекпоинтов без времени изменения доступно текущее состояние блокировки. Тексты HR-обращений и ссылки на них не включаются. Автор может вручную скопировать выбранный фрагмент в тему, предварительно проверив указанную аудиторию.

```json
{"action":"create","id":"aaaaaaaa-aaaa-4aaa-aaaa-aaaaaaaaaaaa","intern_id":"intern_demo_1","scheduled_at":"2030-04-15T12:00:00Z","timezone":"Europe/Moscow"}
```

Отправьте запрос в `POST /api/v1/meetings` с cookie-сессией и действующим Origin. `GET /api/v1/meetings` возвращает встречи и ревизии. Изменение с устаревшей ревизией получает 409.

## Обзор куратора

Полномочие задаётся таблицей `curator_team_assignments` отдельно от роли входа. Демо назначает `mentor_demo_1` на backend-команду. Управление назначениями выполняется оператором БД. Назначение и отзыв меняют версию области доступа.

В «Обзоре адаптации» выберите команду и фильтры. Метрики используют период `[from, to)`, по умолчанию 30 дней, до 366 дней. Группа отображается при наличии как минимум двух разных стажёров.

- Задержки доступа группируются по ресурсу. Ожидание считается от времени создания до текущего времени для ожидающих запросов и до последнего обновления для законченных. Порог включения — 24 часа. Последнее обновление является приближением к времени результата.
- Текущие блокеры группируются по ключу чекпоинта. Длительность считается с последнего изменения состояния или описания. Записи без сохранённой даты не входят в агрегат.
- Рабочие вопросы группируются по активной группе вопросов или ключу чекпоинта. Кадровые вопросы агрегируются по направлению без текстов, личных идентификаторов и ссылок на обращения. Среднее время для вопросов отсутствует.

Счётчики динамики сравнивают первую и вторую половины периода. Сводки и список проблем ограничены 100 строками, доказательства — 50 записями, история карточки — 30 ревизиями. Куратор может сохранить проблему из сигнала или вручную, изменить рабочие доказательства, назначить наставника либо HR по области, объединить проблемы одного типа и направления и зафиксировать решение.

Для шаблона заполните ключи и названия чекпоинтов, проверьте предпросмотр и подтвердите публикацию. Новые планы берут последнюю версию команды. При выборе существующих планов совпадающие ключи обновляют название и описание, новые шаги добавляются в конец. Прежние шаги, статусы, подтверждения и связи сохраняются. Повтор публикации с тем же идентификатором и данными возвращает ту же версию.

## Проверки

- `cd backend` и `go test -v ./internal/app -run 'TestPostgres(Meetings|Curator)'` с тестовой PostgreSQL и `TEST_DATABASE_URL`.
- В `frontend` выполните `npm run test -- src/features/onboarding-operations/operations.test.tsx` и `npm run check:api`.
- Для ручной проверки запустите демо через Compose и создайте встречу и проблему обычными маршрутами приложения.
