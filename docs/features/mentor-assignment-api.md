## Общие правила

- Префикс /api/v1, существующая cookie buddy_session, только роль mentor.
- Principal определяет mentor_id и team_id. Нельзя выбирать их в запросе.
- PUT проходит существующую проверку Origin. Ошибки имеют стандартный ApiError: {error:{code,message,trace_id}}.
- Назначаем только существующего intern своей команды. Не создаём аккаунты, планы, документы или вопросы как побочный эффект.
- Назначение одно на стажёра. Переназначение, удаление назначения и операции между командами не входят в этот этап.
- Наличие плана не является условием назначения. Нет плана: назначение успешно, список назначенных показывает 0 шагов/0% и next_step_id=null, существующий GET плана возвращает 404. UI не откатывает назначение и предлагает повторить загрузку плана позже.
- ИИ не вызывает эти методы; назначение — явное действие наставника.

## GET /api/v1/mentor/available-interns

operationId: listAvailableInterns. Тела и параметров запроса нет. В demo без пагинации; локальный поиск в UI. Возвращает только свободных стажёров команды текущего наставника, в порядке name, id. Пустой результат — 200 с items: [], не null.

Ответ 200, схема AvailableInternList:

```json
{
  "items": [
    {
      "id": "intern_demo_unassigned",
      "name": "Свободный стажёр",
      "team": {
        "id": "team_demo_backend",
        "name": "Тестовая backend-команда"
      }
    }
  ]
}
```

AvailableIntern: обязательные id:string, name:string, team:{id:string,name:string}. Все значения непустые. Никаких планов, прогресса, вопросов, документов, email или сведений о чужих наставниках.
Список — снимок, не резервирование: между GET и PUT стажёра может взять другой наставник.

Ошибки: 401 UNAUTHENTICATED; 403 ROLE_FORBIDDEN; 503 SERVICE_UNAVAILABLE.

## PUT /api/v1/mentor/interns/{id}/assignment

operationId: assignInternToMe. id — строковый ID пользователя, не обязательно UUID. Тело отсутствует, Content-Type не требуется. Любое непустое тело — 422 VALIDATION_ERROR; не принимать mentor_id/team_id. Дополнительный idempotency key и revision не нужны: идентичность операции задают текущий наставник и intern_id.

Новый успех и повтор назначения себе — одинаковые HTTP 200, схема MentorAssignment:

```json
{
  "intern_id": "intern_demo_unassigned",
  "mentor_id": "mentor_demo_1",
  "team_id": "team_demo_backend"
}
```

Все три строковых поля обязательны. Ответ не содержит план и вычисляемый прогресс; после успеха клиент перечитывает существующий GET /mentor/interns. Ответ формируется только после commit. Повтор не создаёт запись и не меняет данные.

Ошибки:

| HTTP | code | Условие |
|---|---|---|
| 401 | UNAUTHENTICATED | Нет действующей сессии |
| 403 | ROLE_FORBIDDEN | Текущий пользователь не mentor |
| 403 | ORIGIN_FORBIDDEN | Отклонён существующей Origin-защитой |
| 404 | NOT_FOUND | ID отсутствует, не intern или принадлежит другой команде |
| 409 | INTERN_ALREADY_ASSIGNED | Intern своей команды уже назначен другому mentor |
| 422 | VALIDATION_ERROR | Передано непустое тело |
| 503 | SERVICE_UNAVAILABLE | Временная ошибка БД/сервиса |

В 409 не раскрывать имя/ID другого наставника. Проверять команду и роль до выдачи конфликта, чтобы чужой ID не раскрывал наличие назначения.

## Конкуренция и восстановление

- Атомарно проверить стажёра и назначить его с уникальностью mentor_assignments.intern_id. Запрещён upsert, перезаписывающий чужой mentor_id.
- Два разных наставника одновременно: один 200, другой 409. Два одинаковых запроса одного наставника: оба 200 с одной записью.
- После timeout/обрыва ответа UI не показывает успех без подтверждения. Перечитать GET /mentor/interns: стажёр найден — назначение подтверждено. Не найден или GET завершился ошибкой — исход пока не подтверждён; доступен явный повтор того же PUT.
- 409: обновить свободных и назначенных, показать конфликт. 401/403/404 и logout обрабатываются по существующим правилам защищённого кеша.
- После успешного commit стажёр исключён из available-interns и доступен через существующий список/план. Новые эскалации используют назначение; исторические вопросы не переписываются.

## Транзакционный порт для #42

Поставка #43 экспортирует:

```go
func (s Store) AssignedInternTx(
    ctx context.Context,
    tx *sql.Tx,
    internID string,
) (identity.Principal, error)
```

Метод в internal/mentor:
- получает mentor из identity.Require(ctx), проверяет роль;
- проверяет назначение текущему mentor, общую команду и актуальные роли обоих users;
- возвращает доверенный Principal стажёра (Role=Intern);
- удерживает FOR SHARE на строках назначения/участников до окончания переданной транзакции;
- не открывает другую транзакцию, не вызывает pool-методы через s.DB и не commit/rollback чужую транзакцию.

Ошибки: identity.ErrUnauthenticated, ports.ErrForbidden для неверной роли вызывающего, ports.ErrNotFound для недоступного intern/назначения, ports.ErrUnavailable для инфраструктуры.
Для подтверждения чекпоинта #42: assignment/users → plan → step, в одной транзакции. Существующий read-only CheckMentor сохраняется для совместимости. Существующие knowledge-gap handlers не переписывать.
