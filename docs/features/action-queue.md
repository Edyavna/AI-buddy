# Требуется моё действие

Пункт «Мои действия» открывает очередь в кабинете наставника или HR. Фильтры по стажёру и типу действия действуют одновременно. Счётчики по типам учитывают выбранного стажёра. Сортировка по возрастанию времени ожидания, при равных датах по типу и ID. Размер страницы по умолчанию 20, максимум 50.

| Источник | Появление | Уход из очереди |
| --- | --- | --- |
| Ручное приглашение | Стажёр просит приглашение из «Организационных моментов» | Стажёр отменяет запрос или назначенный наставник отмечает ручное приглашение |
| Подтверждение | Наставнику доступно `confirm` для политики `mentor` или для `both` после отметки стажёра | Наставник подтверждает чекпоинт, стажёр отзывает обязательную отметку или подтверждение становится недоступным |
| Вопрос наставнику | Открытый рабочий вопрос назначенного стажёра | Вопрос решён или направлен HR |
| Кадровое обращение | Открытое обращение обслуживаемой команды без ответственного или в работе у текущего HR | Вопрос решён, перенаправлен или взят другим HR |

Стажёр может повторить запрос приглашения после отмены или после ручного выполнения. На чекпоинте одновременно активен один запрос. Повтор с тем же UUID возвращает сохранённый запрос. Отмена и отметка наставника относятся к конкретному UUID. Для подтверждений и ответов карточка открывает действующий экран с актуальной ревизией объекта и проверкой прав. Приглашение в корпоративный чат выполняет наставник. Приложение сохраняет его отметку и необязательное пояснение.

## API и данные

```http
GET /api/v1/action-queue?intern_id=intern_demo_1&kind=invitation&limit=20&offset=0
```

```json
{
  "items": [{
    "kind": "invitation",
    "id": "ddc7543a-ac50-4750-9408-fb1a349931f5",
    "intern": {"id": "intern_demo_1", "name": "Тестовый стажер"},
    "step_id": "step_team_setup",
    "step_title": "Организационные моменты",
    "question_preview": null,
    "action": "record_invitation",
    "since": "2026-11-14T10:30:00Z",
    "updated_at": "2026-11-14T10:30:00Z"
  }],
  "interns": [{"id": "intern_demo_1", "name": "Тестовый стажер"}],
  "counts": {"invitation": 1, "confirmation": 4, "question": 0},
  "total": 1
}
```

Очередь опирается на #47/#48 (подтверждения), #53 (каталог чекпоинтов) и общий контракт обращений и области доступа HR из #62. Смена направления из #57 перемещает исходную карточку. Экран обновляется каждые пять секунд, по возврату в окно и при завершении приглашения. Ошибка источника скрывает карточки и выводит повтор загрузки. После изменения назначения используется версия области доступа, общая с кабинетами наставника и HR.

Миграция `000023_action_queue.sql` сохраняет приглашения, время ожидания и время завершения каждого выполненного действия. Для существующих вопросов используется дата создания, для существующих чекпоинтов без события используется время миграции. Время начала ожидания подтверждения учитывает отметку стажёра и даты переходов предусловий. Если подтверждение требует внешней проверки доступа, очередь сверяет текущее право при загрузке, а метрика использует сохранённые даты чекпоинта. События можно агрегировать без текста или идентификаторов пользователей.

```sql
SELECT direction, kind, count(*), avg(completed_at - appeared_at) AS avg_wait
FROM action_queue_completions
GROUP BY direction, kind;
```

## Проверка из чистой среды

```sh
export COMPOSE_FILE=compose.yaml:scripts/compose.hr-test.yaml
docker compose up --build --wait frontend hr-fixture
docker compose --profile demo run --rm seed
npm install --no-save --package-lock=false playwright-core@1.60.0
npx playwright-core install chromium
node scripts/action-queue-browser.mjs
docker compose restart api hr-fixture
docker compose up -d --wait api hr-fixture
docker compose --profile demo run --rm seed
node scripts/action-queue-browser.mjs --verify
```

Скриншоты будут в `tmp/action-queue-browser/` и в артефакте CI `action-queue-browser`. Браузерный тест использует Go, PostgreSQL и существующий детерминированный HTTP-провайдер. Очередь не добавляет вызовов модели.

```sh
# Из backend/ с TEST_DATABASE_URL на сервер PostgreSQL с pgvector и правом CREATEDB.
go test -race -count=1 -coverpkg=./... -coverprofile=coverage.out ./...
mkdir -p coverage
go run ../scripts/go_line_coverage.go --lines coverage.out > coverage/lines.tsv
node ../scripts/hr-coverage.mjs origin/dev backend

# Из frontend/.
npm ci
npm run check:api
npm run typecheck
npm run lint
npm run test:coverage
npm run test:e2e
npm run build
node ../scripts/hr-coverage.mjs origin/dev frontend
```

Скрипт CI печатает список измеренных исполняемых строк и пропуски для каждого изменённого файла. Он исключает generated-типы, тесты, моки и зависимости. PostgreSQL-сценарии отдельно проверяют эффекты SQL-миграции и триггеров.
