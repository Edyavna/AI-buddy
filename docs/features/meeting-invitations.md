# Приглашения на встречу 1:1

Стажёр может открыть редактируемый черновик из последнего ответа чата или начать вручную на странице «Встречи 1:1». Проверяются пять причин для предложения встречи: явная просьба, блокер после обычной попытки решения, согласование приоритетов или решения, обратная связь по результату работы и просроченная договорённость. Для блокера сервер требует заблокированный чекпоинт и открытый вопрос у наставника или уже отправленную заявку на доступ по этому чекпоинту. Если в диалоге выбран шаг, проверка ограничена этим шагом. Для просроченной договорённости учитываются только открытые рабочие договорённости с истёкшим сроком. Если срок на встречу не задан и есть будущая встреча с тем же наставником, можно дополнить её повестку. Подходящая встреча на запрошенное время также открывается для дополнения.

Предложение использует данные своего активного чата. В live-режиме извлечение полей выполняет отдельный вызов модели без инструментов, в demo — локальный разбор. В черновике можно уточнить участника, дату, время и часовой пояс, изменить тему и пункты. Сохранение происходит при нажатии «Отправить приглашение». Собственный HR-диалог и HR-связанные договорённости не используются как источники общих тем.

## API и данные

- `GET /api/v1/meetings/suggestion?message_id=…` возвращает подходящий черновик, `proposal: null` для обычного ответа или ошибку при недоступности модели. Для чата идентификатор операции соответствует пользователю и сообщению и остаётся прежним при повторном открытии.
- `POST /api/v1/meetings` с `action: invite` проверяет назначенного наставника, сохраняет параметры, общие темы и выбор повестки атомарно. Для формы используется `local_at` вида `YYYY-MM-DDTHH:mm` и IANA `timezone`. Два возможных смещения при переводе часов или несуществующее локальное время дают 422. Повтор с прежним UUID и теми же параметрами возвращает текущее состояние операции. Изменённый запрос с тем же UUID даёт 409.
- В `GET /api/v1/meetings` у каждого кандидата есть стабильный ключ `kind + id` и флаг `included`. Операция `agenda` сохраняет выбор по ключу и ревизии. Закрытие вопроса, смена его адресата или временное исчезновение из списка кандидатов не отменяют явно сохранённое исключение. Свои темы редактируются действиями `topic` и `topic-delete`. Для существующей встречи подборку из чата можно добавить через `topics-add`. Личные заметки видит их автор.
- Встреча, отправленная стажёром, начинает со статуса `pending`. Действующий наставник принимает или отклоняет её по текущей ревизии. Повтор того же решения по исходной ревизии идемпотентен. Перенос стажёром возвращает встречу в `pending` и требует нового решения. Участники могут отменить активную встречу и фиксировать итоги после принятия. Назначение и версия проверяются в транзакции.
- `GET /api/v1/meetings/{id}/calendar` отдаёт участнику принятой встречи файл iCalendar со стабильным UID, ревизией, временем в UTC, указанным часовым поясом и ссылкой на карточку. После переноса до повторного принятия, отмены или отклонения экспорт недоступен. Обновление ранее импортированного события во внешнем календаре выполняется вручную.
- Миграция `000028_meeting_invitations.sql` добавляет статусы, детали встречи и сохранённый выбор повестки. Существующие записи `scheduled` продолжают работать.

## Проверки

Node берётся из `frontend/.node-version`. Для Go нужен тестовый PostgreSQL с pgvector и правом `CREATEDB`, перед запуском укажите `TEST_DATABASE_URL`.

```sh
cd backend
go test -race -count=1 -coverpkg=./... -coverprofile=coverage.out ./...
mkdir -p coverage
go run ../scripts/go_line_coverage.go --lines coverage.out > coverage/lines.tsv
cd ..
node scripts/hr-coverage.mjs origin/dev backend
npm --prefix frontend run test:coverage
node scripts/hr-coverage.mjs origin/dev frontend
npm --prefix frontend run check:api
python scripts/check_contracts.py
```

Браузерный сценарий с реальным Go и PostgreSQL запускается из корня репозитория.

```sh
npm install --no-save --package-lock=false playwright-core@1.60.0
npx playwright-core install chromium
docker compose up --build --wait frontend
docker compose --profile demo run --rm seed
node scripts/meeting-invitation-browser.mjs
```

Сценарий проверяет запрос из чата, редактирование черновика, принятие, повторную загрузку, выгрузку файла, запрет для третьего пользователя, перенос и отклонение. В CI порог для изменённых исполняемых строк строго выше 90% отдельно для Go и TypeScript.
