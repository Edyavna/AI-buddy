## Подготовка

Запустить финальный SHA по README. Выполнить seed, для живого поиска — импорт знаний и настройку live.
Использовать отдельные профили браузера для intern_demo_1, mentor_demo_1 и hr_demo_1.
Проверить назначения. Сохранить стартовое состояние в отдельном демонстрационном окружении.
Заранее прогнать формулировки: ответ модели может отличаться.

## Основной путь: от задачи до результата

| Шаг | Действие | Что показать |
|---|---|---|
| 1 | Войти стажёром, открыть план | Текущий шаг, инструкция, доступные действия |
| 2 | Спросить о запуске учебного проекта | Ответ из импортированных знаний и доступный источник |
| 3 | Попросить подготовить нужный доступ | Черновик с ресурсом, правами и обоснованием |
| 4 | Нажать подтверждение | Сохранённая заявка и статус ожидания; права ещё не выданы |
| 5 | Выполнить demo-control list, затем approve с ID заявки по README | Явно сказать, что решение корпоративного сервиса имитируется |
| 6 | Дождаться сверки, обновить страницу | Результат сохранён; доступ и следующий шаг согласованы |

## Развилка и дополнительные возможности

- Вместо одобрения показать отказ либо вопрос без нужного источника: пользователь видит понятный результат.
- Передать кадровый вопрос HR и рабочий наставнику, показать получателя и сохранённый статус.
- Наставник генерирует инструкцию, уточняет текст, скачивает Markdown, затем отдельно загружает в знания.
- Стажёр предлагает встречу, меняет повестку; наставник принимает; стажёр видит статус и скачивает ICS.
- Стажёр сообщает предпочтение, подтверждает память, проверяет и удаляет запись.
- Показать подготовку к ревью и явно различить ручные сведения и полученные CI-проверки.

Выбрать для живой защиты только то, что укладывается в регламент и прошло репетицию.
Не обещать отсутствие ошибок модели по одному удачному вопросу.
