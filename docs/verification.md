## Воспроизводимые автоматические проверки

Версии и команды приведены в [README](../README.md).
Для SQL-тестов требуется отдельный PostgreSQL/pgvector, TEST_DATABASE_URL и право CREATEDB.
Без переменной тесты могут быть skipped. Успешный workflow не означает выполнение каждой условной job.
Frontend test:e2e — Vitest, не самостоятельное доказательство браузерного прогона с Go.
Для контрактов нужны зависимости из contracts/requirements-check.txt.

Для Go после обычных тестов получить профиль:
```sh
cd backend
go test -count=1 -coverpkg=./... -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
go run ../scripts/go_line_coverage.go coverage.out
```
Перед запуском задать TEST_DATABASE_URL по README. Race-проверка требует поддерживаемого C-компилятора.
Go tool cover считает statements; отдельный скрипт проверяет строки.
Frontend: npm run test:coverage из frontend; отчёты находятся в frontend/coverage.
Исключения и пороги проверять в frontend/vitest.config.ts и .github/workflows/backend.yml.

Для защиты требуется строго больше 80% строк прикладного кода.
Не подменять общее покрытие покрытием изменённых строк отдельной фичи.
Сохранить сырые отчёты, команды, исключения, количество passed/failed/skipped и SHA.
Проценты финального покрытия в этот документ пока не внесены: нового полного измерения нет.

## Качество живого агента

Набор должен включать вопросы с ответом в корпусе, без ответа, неоднозначные,
кадровые, рабочие, продолжения диалога и сбои API.
Для каждого: ожидаемый результат, доступные источники, фактический ответ, эскалация,
время, модель и SHA корпуса. Не считать один удачный ответ доказательством качества.

Исторические issue*-coverage и отчёты PR сохраняют силу только для своих версий.
