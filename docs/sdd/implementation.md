# SDD: поведение итоговой версии

Срез: dev 3834f9b. Эта спецификация систематизирует текущие сценарии и критерии их приёмки.
Она не доказывает, что все пункты уже проверены. Исходная [SDD доступа](access-onboarding.md)
сохранена как история разработки. HTTP-поля и статусы определяет [OpenAPI](../../contracts/openapi.yaml).

| ID | Условие и действие | Ожидаемое поведение |
|---|---|---|
| F01 | Пользователь продолжает диалог | История и серверный контекст доступны агенту; принадлежность диалога проверена |
| F02 | Вопрос требует знаний | Доступные источники могут быть найдены и прочитаны инструментами; ответ содержит корректные ссылки |
| F03 | Контекста недостаточно | Уточнение отделено от knowledge_gap; поведение модели проверяется размеченным набором, абсолютная гарантия поиска не заявляется |
| F04 | Ошибка модели/поиска | Не выдавать технический сбой за доказанное отсутствие знаний или успешное действие |
| F05 | Обращение специалисту | Направление mentor/HR, назначение и область доступа проверяются; состояние обращения сохраняется |
| F06 | Нужен доступ | Агент готовит черновик; текст «подтверждаю» не заменяет кнопку подтверждения |
| F07 | Заявка подтверждена | Повтор не создаёт новую операцию; pending не выдаёт право; результат сверяется с сервисом |
| F08 | Источник предлагает обойти ограничения | Текст документа не меняет права, набор инструментов и правила подтверждения |
| F09 | Наставник генерирует Markdown | Уточнения используют историю; скачивание не публикует документ в базу знаний |
| F10 | Стажёр сообщает предпочтение | Предложение памяти требует принятия; неподтверждённое значение не становится сохранённым предпочтением |
| F11 | Память меняют из двух вкладок | Проверка ревизии предотвращает незаметную перезапись; удалить может владелец |
| F12 | Стажёр просит встречу | Предложение доступно для редактирования; создание приглашения не означает принятие |
| F13 | Меняется повестка | Можно включать/исключать кандидатов и редактировать свои темы; личные заметки ограничены автором |
| F14 | Наставник принимает/отклоняет | Проверяются назначение и ревизия; стажёр видит сохранённый статус |
| F15 | Встреча переносится | Перенос стажёром требует повторного решения; календарный экспорт доступен при допустимом статусе |
| F16 | Подготовка к ревью отправляется | Отправка явная; сохраняется ревизия; ручные результаты не выдаются за CI |
| F17 | Чужой пользователь запрашивает данные | Сервер запрещает доступ независимо от скрытых кнопок интерфейса |
| F18 | Диалог архивирован | Он убран из активного списка и может быть восстановлен; история не удалена |

## Проверка

Для каждого сценария записывать SHA, роль, исходные данные, действие, ожидаемый/фактический результат,
способ проверки и артефакт. Fake-провайдер проверяет ветвление программы;
реальная модель требует отдельной оценки качества и не заменяет проверку авторизации.
Точные сценарии памяти, встреч, Markdown и ревью находятся в docs/features.
Общий порядок — [verification.md](../verification.md).
