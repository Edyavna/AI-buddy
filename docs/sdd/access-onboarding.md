# SDD: первая задача и доступ

Статус: спецификация к реализации #10–#14, принята Лёшей 9 ноября 2026.
Она задает будущие проверки. Реальные тесты Ромы/Егора/Лёши будут связаны с IDs ниже
в их PR; перечисление сценария не означает, что проверка уже реализована или прошла.
См. [архитектуру](../backend/architecture.md), [контракт](../backend/interfaces.md).

## Источники истины

Модель выбирает инструмент, но факты о правах возвращает AccessChecker. Статус,
версию и внешний номер возвращает RequestReader. Документы и ACL принадлежат
Knowledge. Подтверждение проверяет request-service, оно не выводится из текста.
Ни один инструмент агента не создает внешнюю заявку или одобрение.

## Данные и виды прогона

Основной набор использует IDs contracts/examples/scenario.json. Для отрицательных
сценариев добавляются второй пользователь той же команды и пользователь другой
команды. Они не получают доступ к объектам первого пользователя. Источники явно
помечены как синтетические, данные сотрудников не используются.

Fake-прогон: детерминированные ответы LLM/embedding и ошибки инструментов, без ключей.
SQL-прогон: настоящие PostgreSQL/транзакции/имитация, без платного LLM.
Live-прогон: настоящий LLM+embedding, Go, имитация и UI. В отчете указываются режим,
модели, конфигурация без секретов, IDs сценариев и фактический результат.
Fake-успех не объявляется доказательством live-готовности.
