# Интеграция с инфраструктурой Авито

Срез: dev 3834f9b. Это карта существующих границ и требуемых интеграционных работ.
Доступа к внутренним API Авито и подтверждения совместимости на реальном стенде нет.

## Что известно из Q&A

Организаторы сообщили о настройке ИИ-агентов с выбором промптов и MCP,
внутреннем ИИ-кроне и feature flags. Есть сервисы корпоративных процессов и заявок на доступ.
Полные API, события и единая схема статусов не предоставлены.
Для прототипа разрешены имитации; полноценную корпоративную систему заявок создавать не требуется.

## Что подключать

| Область | Сейчас | Для внедрения |
|---|---|---|
| Идентификация | Демоаккаунты и сессии | SSO и доверенное сопоставление сотрудников, команд, ролей и назначений |
| Задачи и доступы | Go-порты и демонстрационный адаптер | Реализации к конкретным API, таблица статусов, идемпотентность, сверка результата |
| LLM | Серверный адаптер провайдера | Согласованный endpoint/модель или адаптер внутреннего агента; проверить протокол инструментов и поток ответа |
| MCP | Внутренние инструменты агента | При необходимости обёртка MCP с авторизацией и схемами; готовый внутренний MCP Авито не заявляется |
| Плановые операции | Фоновые обработчики приложения | Определить запуск внутренним кроном, владение задачами, повторы и наблюдаемость |
| Feature flags | Нет подтверждённого подключения к сервису Авито | Флаги пилота, команды/когорты, выключение интеграции и проверяемое поведение при сбое |
| Знания | Markdown, Playbook и Wikipedia | Корпоративный источник с версиями, удалением, ACL и обновлением индекса |
| Календарь | ICS принятой встречи | Адаптер календаря и согласование событий/изменений; ICS остаётся ручным вариантом |
| GitHub | Опциональное получение сведений о PR | Токен с минимальными правами, допустимый сервер, сеть и обработка rate limit |

В текущем compose.yaml переменные GITHUB_TOKEN и GITHUB_API_URL не передаются в api. Для интеграции добавьте их передачу в окружение api через Compose override. Для стандартного демозапуска используйте ручной режим подготовки к ревью.

## Что мы не создаём заново

Имитация выдачи доступа нужна для демонстрации контракта и сохранённого результата.
Она должна заменяться корпоративным сервисом. Локальный индекс знаний и Markdown-загрузка
демонстрируют управление источниками; наличие корпоративного агента само по себе не обеспечивает
нужный корпус, его актуальность и права. Если внутренний сервис предоставляет это полностью,
следует подключить его вместо дублирования хранения и поиска.

Сохраняем продуктовый слой: адаптацию, подтверждения, контекст общения, очередь вопросов,
подготовку встреч/ревью и отображение результатов. Окончательную границу определяют владельцы внутренних API.

## Минимальный путь пилота

1. Получить sandbox и согласовать модель прав, источники и допустимые данные.
2. Подключить идентификацию и одну команду с наставником/HR.
3. Заменить один адаптер: чтение задачи, проверка доступа, отправка заявки, чтение результата.
4. Проверить одинаковый ID при повторе, таймаут после отправки, отказ, смену назначения и отзыв доступа.
5. Подключить разрешённые знания и LLM, прогнать размеченные вопросы.
6. Включить ограниченный пилот; измерять ошибки, задержки и нагрузку на наставника.

## Что требуется от владельца сервиса

Endpoint и протокол; способ авторизации; идентификаторы пользователей/ресурсов;
статусы и переходы; лимиты; правила повторов; webhooks или polling; SLA; тестовые данные;
требования к журналам, хранению и удалению. Секреты не включать в документацию или репозиторий.

## Безопасность и эксплуатация

До production нужны SSO, HTTPS, управление секретами, резервирование и восстановление БД,
политика хранения персональных данных, аудит доступа и проверка отправки данных провайдерам.
Это перечень работ для внедрения, а не утверждение об уже проведённом аудите.
Оценку сроков подключения можно дать после получения API; обещание «заменить один URL» необоснованно.
