# AvitoTech Playbook в базе знаний

Для демо используем коммит [0c1d2aa1501ca6889357908f54b12695f0534e48](https://github.com/avito-tech/playbook/tree/0c1d2aa1501ca6889357908f54b12695f0534e48) с 28 Markdown-файлами. Импортёр читает зафиксированные Git-объекты и разбивает материалы на части до 16 000 символов. В просмотрщике «Открыть в GitHub» ведёт к исходному файлу на коммите импортированного текста. Playbook доступен всем стажёрам в поиске по рабочим и HR-вопросам.

## Первичный импорт

В `.env` задайте `AI_MODE=live` и параметры DeepSeek и Jina из [.env.example](../../.env.example). Выполните из корня AI-buddy.

```sh
git clone https://github.com/avito-tech/playbook.git ../AvitoTech-playbook
docker compose up --build --wait frontend
docker compose --profile demo run --rm seed
docker compose --profile demo run --rm knowledge-import
docker compose --profile playbook run --rm --build playbook-import -repo /playbook -commit 0c1d2aa1501ca6889357908f54b12695f0534e48
```

Если клон лежит в другом месте, задайте `PLAYBOOK_REPO` для Compose. Для локального запуска без Compose задайте `DATABASE_URL`, `EMBEDDING_BASE_URL` и `EMBEDDING_API_KEY`, затем выполните из `backend`.

```sh
go run ./cmd/migrate
go run ./cmd/playbook-import -repo ../../AvitoTech-playbook -commit 0c1d2aa1501ca6889357908f54b12695f0534e48
```

Флаг `-check` проверяет Git-снимок и выводит число файлов и частей без подключения к БД и Jina. Повтор команды для того же снимка показывает ноль новых и архивированных частей.

## Обновление

После приёмки демо обновите локальный клон и определите SHA новой версии.

```sh
git -C ../AvitoTech-playbook fetch origin master
git -C ../AvitoTech-playbook rev-parse FETCH_HEAD
```

Передайте полученный полный SHA в ту же команду импорта. Для планового запуска выполняйте эти команды в одной задаче и запускайте импорт только после успешного `fetch`. Если два импорта пересекутся, один из них может завершиться конфликтом. Повторите команду с нужным SHA.

Неизменившиеся файлы сохраняют прежние идентификаторы и ссылки. Новые и изменившиеся части публикуются одной транзакцией после получения всех эмбеддингов. В этой же транзакции удалённые и заменённые части исключаются из поиска. Просмотрщик по-прежнему открывает сохранённый текст этих частей по ссылкам из истории чата. Для возврата к предыдущему снимку запустите импорт с его SHA.

## Живая приёмка

Проверьте, что среди первых пяти результатов есть ожидаемый файл. Команда проверки обращается к тому же поиску с Jina и правами демостажёра. Для кадровых вопросов укажите `-direction hr`. Идентификаторы другого стажёра и его команды можно передать через `-intern` и `-team`.

```sh
docker compose --profile playbook run --rm playbook-import -direction mentor -query "Что такое LSR?"
docker compose --profile playbook run --rm playbook-import -direction hr -query "Из каких этапов состоит отбор инженеров?"
```

Для каждого промаха запишите вопрос, направление поиска и полученные файлы. Затем задайте в чате как минимум вопросы про LSR, Scrum, собеседования и набор 2021 года. Проверьте, что ответ называет AvitoTech Playbook, а карточка источника открывает тот же текст в приложении и ведёт на нужный коммит в GitHub.
