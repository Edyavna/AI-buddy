# Эксплуатация демонстрационного стенда

Срез: dev 3834f9b. Единственный источник команд установки, версий, переменных,
импорта, тестов и диагностики — [README](../README.md). Не используйте старые команды из отчётов поставок.

## Первый запуск

Клонировать dev, записать SHA, создать .env, проверить Docker, выполнить запуск и seed по README.
Для live заполнить провайдеров, пересоздать сервисы и импортировать знания.
Seed создаёт аккаунты; файл Wikipedia в образе ещё не является поисковым индексом.
На Windows порт БД может быть занят или зарезервирован: использовать override из README.

## Перед демонстрацией

Проверить healthz/readyz, аккаунты, наличие нужного корпуса, лимит провайдеров и основной сценарий.
Health не проверяет качество ответа LLM. Отдельно проверить живой запрос.
Использовать синтетические данные и отдельную базу для репетиции.
Не удалять том рабочего стенда для повторного показа.

## Обновление и восстановление

Сохранить нужные данные, обновить исходники и пересобрать контейнеры по README.
Не редактировать применённые миграции. Проверить совместимость схемы перед откатом кода.
Резервная копия считается проверенной только после восстановления на отдельной БД.
Импорт календаря повторяется вручную; автоматической синхронизации нет.

## Сбой

Сохранить время, SHA, этап и безопасный фрагмент ошибки без ключей/cookie.
Посмотреть compose ps и логи соответствующего сервиса.
При неопределённом результате внешней операции сначала проверить её статус, не создавать новую.
При недоступности LLM явно показать ограничение; demo не выдавать за живую модель.
